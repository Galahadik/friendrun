# Draft+ — техническая спецификация

Статус: продуктовые правила согласованы; отдельные технические детали реализации отмечены в разделе 15.
Целевая ветка: `feature/draft-plus`.
Базовая ветка: `main` (не изменять и не сливать без отдельного решения).
Целевая платформа: Minecraft Java 26.3, Fabric, Java 25.

## 1. Границы и совместимость

- Draft+ — отдельный игровой режим со своим состоянием, сетевым протоколом, экранами, результатами, историей и рейтингами.
- Классический Draft (Game.DRAFT), его экран, алгоритм, данные, сериализация и рейтинг не изменяются.
- Draft+ никогда не обновляет общий MMR профиля.
- Draft+ FFA и Draft+ Team имеют независимые MMR, таблицы лидеров и историю матчей.
- Разработка ведётся только в `feature/draft-plus`. `main` не изменять и не мержить без отдельного решения пользователя.
- Сервер/хост является авторитетным источником состояния матча, случайности, проверок действий, результата и рейтинга.

## 2. Форматы матча и условия запуска

### FFA
- От 1 до 10 игроков.
- Каждый игрок захватывает клетки лично.
- Победа: первый игрок, захвативший 13 клеток из 25.
- Рейтинговый FFA доступен при 2–10 игроках.
- При одном игроке доступна одиночная тренировка; MMR не меняется.

### Team
- Всегда две команды.
- Размер команды в лобби: от 1×1 до 5×5.
- Игроки могут самостоятельно вступать/перемещаться между командами; хост может использовать случайное распределение.
- Первый занявший место в команде становится капитаном.
- Капитан может менять название своей команды. Другие полномочия капитана не добавлять без согласования.
- Названия команд видны в интерфейсе вместо «Команда 1/2».
- Победа: команда, участники которой суммарно захватили 13 клеток из 25.
- Рейтинговый Team доступен при наличии минимум двух игроков в каждой команде.
- При меньшем количестве игроков можно запускать Training без изменения MMR.

### Rated / Training
- Хост выбирает тип матча: Rated или Training. По умолчанию — Training, чтобы рейтинговая игра всегда включалась осознанно.
- Training не меняет MMR при любом количестве игроков.
- Остальные игровые механики Training работают по тем же настройкам, что и Rated.
- Нельзя автоматически переводить Training в Rated или наоборот после старта.

## 3. Доска и фаза драфта

- Общая доска для всех участников, всегда 5×5 (25 клеток).
- На каждом ходе текущий игрок видит два варианта целей и выбирает один.
- Выбранная цель помещается на общую доску. Драфт завершается после заполнения всех 25 клеток.
- После драфта начинается игровой этап: участники выполняют цели на доске и захватывают соответствующие клетки.
- Клетка захватывается игроком после выполнения соответствующей цели; в Team захват засчитывается команде игрока.
- Все участники видят оба варианта и имя выбирающего.
- Текст состояния: «Сейчас выбирает: [имя]»; после выбора — «[имя] выбрал: [цель]».
- Выбрать вариант может только игрок текущего хода; сервер проверяет игрока, фазу, номер хода, выбранный вариант и отсутствие повторной обработки.
- FFA: круговой порядок игроков, стартовый игрок определяется монеткой.
- Team: команды чередуются A → B → A → B; внутри команды игроки выбирают по кругу.
- В Team монетка определяет стартующую команду; первая очередь внутри команды идёт по кругу.
- После банов выполняется отдельная случайная жеребьёвка первого хода драфта. Результат/анимация видны всем.
- Монетка всегда включена, её нельзя отключить. Каждый матч получает новую серверную жеребьёвку.
- Случайные результаты вычисляются только авторитетной стороной; клиенты не выбирают их самостоятельно.

## 4. Баны

- Баны можно отключить настройкой лобби.
- Team: капитаны команд по очереди банят по два предмета; всего четыре бана.
- FFA: случайно определяется первый игрок; игроки банят по очереди, всего три бана.
- Забаненные цели полностью исключаются из пула матча и не могут появиться в драфте.
- Пул Draft+ включает:
  - предметы Minecraft из настроенного хостом пула;
  - FriendRun quests;
  - Minecraft advancements.
- Персональные advancement-цели, уже выполненные конкретным игроком, не должны предлагаться ему как невыполнимые; персонализация не должна создавать дубли на доске.

## 5. Роли

- В лобби есть переключатель «Роли: Включены/Выключены». Менять его может только хост.
- Если роли включены, каждый игрок обязан выбрать одну из шести ролей; выбор виден всем. Без выбора любого участника старт запрещён.
- Повторение ролей разрешено, в том числе внутри одной команды.
- Если роли выключены, выбор ролей не требуется и бонусы не применяются.
- Хост фиксирует настройки и роли при запуске матча. Во время матча менять их нельзя.
- Выбранные роли сохраняются в лобби для следующих матчей.
- Бонусы применяются временными серверными модификаторами атрибутов только в Draft+; зелья не используются. Модификаторы должны корректно переживать countdown, running, смерть/respawn и реконнект и удаляться после матча/выхода.
- Утверждённые роли:
  - Скороход — +10% к скорости передвижения.
  - Шахтёр — +15% к скорости добычи блоков.
  - Страж — +4 к максимальному здоровью.
  - Боец — +1 к силе атаки.
  - Акробат — +15% к силе прыжка.
  - Пловец — +0,20 к атрибуту эффективности движения в воде.

## 6. Хаос-модификаторы

- Хаос-модификаторы включаются/выключаются хостом.
- По умолчанию хаос-модификаторы включены, количество по умолчанию — 1.
- Количество: 1 / 2 / 3 / Случайно (1–3).
- Сложность: Лёгкая / Средняя / Высокая.
- Если хаос выключен, количество и сложность не влияют на матч.
- Перед матчем сервер случайно выбирает модификаторы; голосования нет.
- Все участники видят одинаковый список и играют по одинаковым правилам.
- Модификаторы действуют до конца матча и не меняются по ходу игры.
- Первоначальный пул состоит ровно из пяти модификаторов:
  1. Богатый урожай — небольшой / заметный / большой бонус при сборе полностью созревших культур.
  2. Железная лихорадка — при добыче железной руды дополнительно выпадает +1 / +2 / +3 сырого железа.
  3. Опасная ночь — враждебные мобы получают +10% / +20% / +35% здоровья и урона.
  4. Быстрый крафт — шанс получить дополнительный экземпляр результата крафта: 10% / 20% / 30%.
  5. Дефицит ресурсов — случайная категория ресурсов добывается на 10% / 20% / 30% меньше.
- Эти пять эффектов — согласованный начальный пул для первой версии. Не расширять его без отдельного решения.
- До реализации каждого эффекта проверить доступные hooks/events в целевой версии 26.3; не применять неподтверждённые устаревшие Fabric API.

## 7. Настройки лобби

- Только хост меняет настройки; остальные участники видят их read-only.
- Настройки: роли on/off, баны on/off, хаос on/off, количество хаос-модификаторов, сложность хаос-модификаторов, Rated/Training.
- Team size, названия команд и состав команд доступны в командном лобби.
- Монетка не является настраиваемым переключателем: она всегда включена.
- Перед стартом хост фиксирует настройки матча; frozen snapshot синхронизируется со всеми участниками.
- Новый хост после миграции может управлять лобби/матчем, но не может менять зафиксированные параметры уже начавшегося матча.

## 8. Победа, ничья и завершение

- При достижении 13 клеток игроком/командой победа фиксируется немедленно.
- Если заняты все 25 клеток, побеждает игрок/команда с наибольшим числом клеток.
- Если лидеры имеют одинаковое число клеток — ничья.
- При досрочном завершении Rated-матча хост отправляет запрос всем оставшимся участникам. Матч завершается только при согласии всех.
- При согласии результат определяется по текущему счёту клеток: лидер побеждает, равный счёт означает ничью. MMR рассчитывается по обычной Elo-формуле и личному вкладу.
- В Training хост может завершить матч в любой момент; MMR не меняется.
- Если игрок отключился, ему даётся 5 минут на реконнект. Вернувшийся продолжает матч с восстановленным состоянием; если не вернулся, получает поражение. FFA/Team продолжаются без него.
- В Team после истечения 5 минут команда продолжает матч. Рейтинг оставшихся игроков рассчитывается по командному результату; отключившийся игрок отдельно получает поражение.
- Если хост отключился в Rated-матче, полномочия немедленно передаются другому участнику; матч продолжается. Вернувшийся прежний хост становится обычным участником. Новый хост не может менять frozen settings, роли, баны или хаос-модификаторы.
- Если все участники отключились и никто не вернулся за 5 минут, матч завершается автоматически: лидер по клеткам побеждает; при равном счёте — ничья; если результат определить невозможно (например, доска пуста) — матч отменяется без изменения MMR.

## 9. Рейтинг и статистика

- Три независимых пространства: классический Draft (существующий, без изменений), Draft+ FFA и Draft+ Team.
- Draft+ FFA и Team имеют отдельные MMR, leaderboard и match history.
- Начальный MMR: 1000 отдельно для каждого игрока в FFA и Team.
- Elo K-factor: 32.
- Победа/поражение/ничья — основной фактор рейтинга.
- FFA: каждый игрок сравнивается со всеми остальными участниками попарно; фактический результат пары определяется числом захваченных клеток (победа/поражение/равенство), ожидаемый — стандартным Elo. Итоговое изменение агрегирует все попарные сравнения.
- Team: сначала рассчитывается средний MMR каждой команды; командный Elo учитывает ожидаемый результат по разнице средних рейтингов. Все игроки команды получают одинаковое базовое изменение MMR.
- После командной базовой корректировки к каждому игроку применяется личная поправка от −5 до +5 MMR.
- FFA также получает личную поправку от −5 до +5 MMR.
- Личный вклад учитывает редкие/ключевые ресурсы, получение ключевых предметов и реальное участие в захватах клеток. Начальные веса: +1 за каждый уникальный редкий ресурс, +2 за каждый уникальный ключевой предмет, +1 за каждую захваченную клетку. Итог сравнивается со средним вкладом участников матча, округляется до целого и ограничивается диапазоном ±5 MMR.
- Повторное получение того же item ID не увеличивает вклад: учитываются только уникальные типы предметов, а не количество стаков. Это базовая антифарм-защита для первой версии; веса и списки редких/ключевых предметов можно менять после тестов.
- Личный вклад не может перевесить командный результат в Team; базовая командная Elo-часть всегда рассчитывается отдельно.
- Training никогда не меняет рейтинг.
- Ничья использует стандартный Elo actual score 0.5.
- Рейтинги, история и статистика Draft+ хранятся отдельно от существующих узлов/ключей общего MMR.

## 10. Экран результатов, история и рематч

- После матча показывать подробный экран:
  - победитель/проигравшие или ничья;
  - итоговый счёт клеток;
  - изменение MMR каждого игрока;
  - личный вклад участников;
  - роли;
  - активные хаос-модификаторы;
  - длительность;
  - статистика захваченных клеток.
- Для Training показывать явную отметку «Тренировочный матч» и отсутствие изменения MMR.
- История матчей раздельная для FFA и Team. Сохранять дату, длительность, формат, игроков/команды, победителя/счёт, MMR delta, роли и хаос-модификаторы; дать возможность открыть прошлый матч.
- «Сыграть ещё раз»: оставить игроков в том же лобби, сохранить настройки и выбранные роли, сбросить доску/статистику, заново провести баны, монетку, выбор хаоса и полный драфт.
- «Выйти в лобби»: вернуться в лобби без запуска нового матча.
- Перед повторным матчем хост может изменить настройки.

## 11. Исключения игроков

- Функцию исключения/kick игроков не добавлять ни в лобби, ни во время матча.

## 12. Интерфейс и HUD

- Визуально соответствовать существующему FriendRun.
- Переиспользовать `Ui.backdrop`, `Ui.panel`, `Ui.frame`, `Ui.button`, `Gfx`, `Icons`, существующие палитру, размеры, отступы, типографику и анимации.
- Локализация ru/en/uk.
- Показывать названия команд, текущего выбирающего, ход/прогресс доски и доступность действий.
- HUD: компактная доска 5×5; увеличенная доска в инвентаре с tooltips и статусом захвата. Сетка не должна перекрывать vanilla inventory/crafting UI и должна адаптироваться к доступному размеру экрана.

## 13. Архитектура и сетевые требования

- До изменения любых общих enum/счётчиков/таблиц проверить все места, зависящие от `Game.COUNT`, `Game.name`, `Ranking.MODE_KEYS`, `Ranking.MODE_SHORT`, `Ranking.key`, leaderboards и сериализации.
- Не добавлять Draft+ в общий путь расчёта рейтинга, обновляющий общий MMR.
- Отдельные Firebase nodes/keys для Draft+ FFA и Draft+ Team; состояние Draft+ отдельно от классического Draft.
- Host-authoritative: сервер проверяет запросы банов, выбора, захвата, смены ролей/настроек, жеребьёвки, победителя и результата.
- Случайность только на авторитетной стороне.
- При реконнекте отправляется полный snapshot, достаточный для восстановления текущей фазы, доски, таймеров, настроек, ролей и статуса матча.
- Все критические действия идемпотентны; повторная доставка Firebase-события/пакета не должна повторно засчитывать выбор, захват или изменение MMR.
- Host migration не сбрасывает матч, его frozen settings или уже зафиксированный прогресс.
- Состояние и эффекты Draft+ должны полностью очищаться после матча; классический Draft должен работать без изменений.

## 14. Текущая реализация (проверять по коду, не считать все пункты завершёнными)

В ветке уже присутствуют отдельные доменные классы Draft+ для правил, потока банов/драфта, команд, ролей и Firebase codec; интеграция с Lobby/FriendRunClient; HUD; начальные unit tests. Также реализованы отдельные UI для выбора режима/команд и роль-модификаторы.
Это не означает, что все согласованные функции завершены. Перед следующими изменениями нужен аудит текущей реализации и gap list по требованиям выше. Известные области, требующие реализации/проверки: полная настройка и snapshot лобби, реальный runtime capture/progress, chaos effects, disconnect/reconnect и host migration, рейтинги и Firebase persistence, подробный экран результата/history/rematch, lifecycle всех ролей, локализация, сетевые/регрессионные тесты.

## 15. Технические детали, требующие осторожной реализации

- Для FFA pairwise Elo использовать попарные сравнения всех игроков с фактическим результатом по числу клеток: 1 / 0.5 / 0. Формула должна быть детерминированной и zero-sum до личной поправки.
- Для Team использовать стандартный Elo expected score на основе среднего MMR команд; базовое изменение одинаково для участников равных по размеру команд.
- Личный вклад ограничен ±5 MMR; начальные веса и антифарм-правила зафиксированы в разделе 9 и покрыты unit tests. Не менять ограничение без согласования.
- Если в матче нет достаточных данных для достоверного вклада, безопаснее применить 0 contribution adjustment, чем выдумывать статистику.
- Перед изменением Fabric hooks сверяться с официальной документацией/исходниками именно ветки 26.3; некоторые старые API удалены или заменены.
- Проверять все эффекты Chaos отдельно: урожай/loot, добыча руды, атрибуты мобов, выдача результата крафта, снижение добычи. Если для эффекта нет надёжного hook в 26.3, выбрать безопасную совместимую реализацию, не менять согласованную механику молча.

## 16. Порядок разработки

1. Составить аудит текущего кода по разделам 2–15 и список пробелов/рисков.
2. Завершить доменные модели и полную синхронизацию настроек/состояния Draft+.
3. Завершить командное лобби, баны, жеребьёвки и драфт 25 клеток.
4. Завершить выполнение целей, захват клеток, счёт и завершение матча.
5. Завершить роли и пять согласованных Chaos-модификаторов.
6. Завершить disconnect/reconnect, host migration и полный snapshot.
7. Реализовать изолированные FFA/Team рейтинги, статистику, историю и экран результатов.
8. Реализовать rematch/выход в лобби.
9. Добавить unit/integration/regression tests, проверить сборку и отсутствие влияния на классический Draft.
10. После завершения реализации пользователь проводит multiplayer тестирование с друзьями; найденные баги исправляются отдельными итерациями.
